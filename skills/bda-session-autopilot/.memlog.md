- (decision) Agent type: autonomous (memory + PULSE) -- needs to track which sessionN entries in topics.txt have been built
- (decision) Relationship depth: focused domain tool, not deep companion -- configuration-style First Breath
- (decision) Capability: reference the installed bda-weekly-deliverables skill for build/validate; no internal reimplementation
- (decision) Wake schedule: weekly on Saturday (class is Tuesday; gives ~3 days lead time to review before class)
- (decision) Notification: push notification on pulse completion (success or blocked)
- (decision) Autonomy level: best-effort content brief + flag assumptions in notification, matching bda-weekly-deliverables' documented unattended fallback -- no sign-off gate
- (decision) Skill name: bda-session-autopilot
- (decision) Extra capability: re-review flag if an already-built session's topic text in topics.txt changes -- never silently rebuilds/clobbers
- (decision) Extra capability: build history kept in sanctum memory (date, session, status, assumptions) so the agent can answer what it built or what's pending
- (decision) Extra capability: fail loud not partial -- on knit/lint failure mid-pulse, stop and notify with reason, never leave broken/half-built files
- (gap) Declined: repeating the Keynote known-gap warning on every completion notification (user only wants the other three extra capabilities)
- (gap) Caught during testing: check-pending-sessions.py initially bucketed ALL historical topics.txt entries, which would have made a Pulse try to auto-build session1 (07/25/2026, already past). Fixed: script now defaults to the latest entry only (matching current_topic.py's own default targeting); added --all for explicit audits, never used for auto-build
- (decision) Not evolvable (owner can't teach new capabilities at runtime) -- narrow, fixed-purpose automation tool; kept lean rather than adding the Learned-capabilities mechanism
- (decision) Not customizable (no override surface in customize.toml) -- default no per build process, no concrete org-mandated pre-sanctum-load need exists
- (decision) Diverged from the agent-name convention '{module}agent-{name}': shipped frontmatter/folder name as 'bda-session-autopilot' (no agent- prefix) to match this project's existing bda-* skill naming (bda-weekly-deliverables), per explicit user approval of that exact string
- (decision) First Breath style: configuration (focused domain tool), not calibration -- 5 domain discovery questions authored covering review habits, assumption tolerance, hands-off signals, escalation threshold, and topic-lead-time
