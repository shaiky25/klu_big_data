1 Technique — Analogical Thinking

The Blood Test Panel

The session's founding move: treat model diagnostics as a check-up. A dataset walks in, the model runs its panel, and every metric comes back with a flag. Three ideas fell out of chasing that one analogy.

Lab Report — Diagnostic Panel REF// analogical-thinking
Diagnostic MetricFlagged

Each metric is rendered as its own lab-result card. A red flag / warning icon fires when it fails threshold; green when it's within normal range.

"Your R² came back a little low, Doctor."
Second OpinionNormal

Cross-validation, reframed: re-running the model on a holdout set is asking another doctor to confirm the first diagnosis before anyone panics.

Same patient, unseen data, same verdict?
The Lab MachineCalibrated

The R program — or the database analytical function — is the machine. Dataset goes in one end; the standard fit → score → evaluate protocol runs every time.

Same machine, every patient, no exceptions.
Direction noted: students should grasp the visual result even without following the R code — so the code carries plain-English, self-explanatory comments, not clever idioms.
Direction noted: the audience has zero prior R experience — the walkthrough assumes nothing, not even "programmer-adjacent."
2 Technique — Inner Child Conference

The Patient Case Files

The second technique gave the failure modes a childhood. A bad model isn't "wrong" — it's sick: it caught bad data like germs, or it grew up with one of two familiar habits.

Case File · Overfitting

The Kid Who Memorized

Diagnosis: aced the practice test, bombed the real one.

"I memorized instead of learning."
℞ Cure: fresh, unseen practice data — force the model to actually generalize instead of reciting the answer key.
Case File · Underfitting

The Kid Who Wasn't Paying Attention

Diagnosis: too lazy or inattentive to notice the pattern in the room.

"I wasn't paying attention."
℞ Cure: more parameters and variables to actually attend to — give the model something worth noticing.

Chosen direction: the blood-test-panel framing drives the whole diagnostics section — lab-result cards, red/green flags. Overfitting and underfitting are personified as illness, with kid-simple one-liners as the memorable hook. Fit → score → evaluate is shown as one repeatable protocol, run twice — R locally, then a database analytical function — unifying cross-validation and DB-analytics into a single demo. Deck: 15–20 slides, all ideas must-have but light-touch, viz + code should-have, further reading could-have, walkthrough spanning multiple common ML models.
